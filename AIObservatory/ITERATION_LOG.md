# Prompt Categorization Iteration Log

This document tracks the systematic refinement of the Unsupervised Machine Learning (TF-IDF + K-Means) pipeline used for categorizing prompts. It documents the roadblocks encountered, the architectural pivots, and the back-to-back iterative changes made to optimize the model's accuracy from the very beginning of the project.

## Challenge Overview
The objective was to categorize millions of user prompts into enterprise taxonomies without relying on slow, expensive Deep Learning or LLM APIs (Zero-Dependency). This required traditional ML (TF-IDF), which brought challenges with lexical matching, high-dimensional data clustering, multilingual noise, and semantic intent dilution.

## Iteration History

| :--- | :--- | :--- | :--- |
| **1. Initial Baseline** | Built zero-dependency pipeline. | Required an offline, fast approach to cluster millions of prompts without external APIs. | - Implemented TF-IDF vectorization and HDBSCAN clustering.<br>- Optimized SVD components to speed up processing for large datasets. |
| **2. Multilingual Isolation** | Built offline language routing. | Prompts contained Spanish, French, and German, which confused the TF-IDF clustering math. | - Created a zero-deep-learning statistical language pre-processor.<br>- Decoupled dictionaries into JSON for 7 languages.<br>- Filtered non-English prompts out of the main pipeline. |
| **3. Algorithm Pivot** | Swapped HDBSCAN for KMeans. | HDBSCAN suffered from "high-dimensional clustering collapse" on 1.2M sparse text vectors, resulting in massive unusable clusters. | - Replaced HDBSCAN with `MiniBatchKMeans`.<br>- Enabled multi-threading, then reverted to single-core to preserve memory stability during batch processing. |
| **4. Hybrid Zero-Shot Engine** | Implemented 2-tier categorization with a dynamic fallback bucket. | Pure unsupervised clustering produced categories that didn't align with business goals. | - Implemented a Zero-Shot router to map prompts to 20 official categories first.<br>- Added N-Gram naming and a KMeans fallback bucket ("Other") for unmapped prompts.<br>- Built recursive mega-cluster splitting for the fallback bucket. |
| **5. Taxonomy Enrichment** | Built a hidden mapping layer. | TF-IDF is a lexical keyword-matcher, not a semantic engine. It couldn't link "AWS" to "Cloud Infrastructure". | - Engineered a `Taxonomy Enrichment` dictionary mapping hundreds of enterprise jargon terms to official categories.<br>- Lowered cosine threshold to 0.01 to forcefully vacuum prompts into the taxonomy. |
| **6. Language Router Fix** | Fixed English prompts leaking into the non-English bucket. | The `langdetect` library was misclassifying heavy code/jargon (e.g., Python scripts, SQL) as non-English due to punctuation and acronyms. | - Bulletproofed the language detection heuristic with regex and length filters to safely ignore code blocks and technical acronyms. |
| **7. Architectural Overhaul** | Complete rebuild of the Taxonomy and similarity thresholds. | The original LLM taxonomy was ambiguous. The enrichment logic combined with the 0.01 threshold caused rampant false positives (TF-IDF Greediness). | - Scrapped the original LLM taxonomy and enrichment layer.<br>- Built a mathematically optimized, orthogonal taxonomy with distinct noun-based keywords.<br>- Increased the cosine similarity threshold to force stricter matching. |
| **8. Optimization Round 1** | Mapped missing American Express themes and purged initial noise. | The first run on the new taxonomy left a massive "Other" bucket (~824k prompts) because AMEX-specific themes were missing. | - Created `Category 11: American Express & Payments`.<br>- Added 14 new subcategories mapping specific AMEX themes (Card Members, Offers).<br>- Added first batch of conversational filler ("need", "make", "want") to `custom_noise`. |
| **9. Optimization Round 2** | Mapped 15 technical subcategories and erased Spanish/foreign noise. | The "Other" bucket dropped to 663k. Large clusters formed around generic conversational fragments (e.g., `difference_non`). | - Added 15 granular subcategories (Real Time Streaming, Confluence, iOS/Android, Data Types, SOX Compliance).<br>- Banished 60+ English, Spanish, and generic nouns/verbs to the `custom_noise` filter. |
| **10. Optimization Round 3** | Mapped 10 internal tool/niche subcategories and purged more filler. | The "Other" bucket dropped to 542k. The algorithm started surfacing internal AMEX tools, Slack communications, and Gen AI tasks. | - Added 10 niche subcategories (Lumi SDE, Privacy/PII, PySpark, Slack Message, Visio Diagrams, Gen AI Prompts).<br>- Added 65 more filler words (e.g., `change`, `list`, `question`) to the `custom_noise` filter. |
| **11. Optimization Round 4** | Mapped 8 business/HR subcategories and addressed intent dilution. | The "Other" bucket dropped to 495k. ---
*Note on Semantic Search Trade-Offs*: During Round 4, a major architectural limitation was documented. TF-IDF acts as a lexical keyword-matcher, not a true semantic engine. Aggressively filtering action verbs (e.g., "optimize", "analyze") reduces the engine to noun-based topic modeling, losing the intent of *what* the user is doing to the noun. To combat this without switching to a computationally expensive Local Embedding model (Deep Learning), the pipeline relies on Bi-Grams (`ngram_range=(1, 2)`) to capture multi-word intent (e.g., "optimize code") while filtering out the standalone verb.
